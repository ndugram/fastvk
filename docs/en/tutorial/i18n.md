# Internationalization (i18n)

FastVK ships a small JSON-catalog translator and a middleware that resolves
the locale for every update.

## Catalogs

Create one `<locale>.json` per language — a flat `{key: text}` map:

```
locales/
  en.json   {"hello": "Hello, {name}!", "bye": "Goodbye"}
  ru.json   {"hello": "Привет, {name}!", "bye": "Пока"}
```

## Wiring it up

```python
from fastvk import FastVK
from fastvk.middleware.i18n import I18n, I18nMiddleware
from fastvk.types import Message

i18n = I18n("locales", default_locale="ru")
bot = FastVK(token="vk1.a.YOUR_TOKEN", middleware=[I18nMiddleware(i18n)])


@bot.message()
async def hello(message: Message, i18n: I18n) -> None:
    await message.answer(i18n("hello", name=message.from_id))
```

`i18n("key", **kwargs)` looks up `key` in the active locale, falls back to
`default_locale`, then to the key itself, and `str.format(**kwargs)` fills in
placeholders.

## Locale resolution

By default the middleware reads `client_info.lang_id` (callbacks) or
`message.lang` from the raw update. Override with a custom getter — e.g. from
your database:

```python
async def get_locale(event) -> str | None:
    user_id = getattr(event, "from_id", None) or getattr(event, "user_id", None)
    return await db.get_locale(user_id)

I18nMiddleware(i18n, locale_getter=get_locale)
```

## Outside handlers

The active locale lives in a `ContextVar`:

```python
I18n.get_locale()          # current locale string
I18n.set_locale("en")      # override within the current task
i18n.gettext("hello", locale="en", name="Sam")   # explicit locale
```

Call `i18n.reload()` to re-read the catalog files at runtime.
